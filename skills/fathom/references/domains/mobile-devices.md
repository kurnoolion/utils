# Domain pack — mobile OS, apps, handsets

## Primary sources (decide)
- Platform vendor developer docs, API diffs, beta release notes, developer-conference session transcripts, app-store review guidelines and policy changelogs.
- Open-source OS trees and kernel commits where the platform is open; security bulletins.
- Hardware truth: regulator equipment-authorization filings and test reports (bands, power), certification listings (Bluetooth SIG, Wi-Fi Alliance, USB-IF), GSMA TAC records, OEM spec pages per region SKU, teardowns (iFixit, TechInsights).
- Money and volume: OEM and supplier earnings transcripts, supply-chain filings, shipment trackers (IDC, Counterpoint, Canalys — note methodology and revisions).
- Patents: read the claims, not the abstract; a filing is intent, not a roadmap.

## Secondary (frame, not decide)
Reporters and analysts with a scored track record; trade-press roundups; developer forums and issue trackers (discovery for real-world behaviour).

## Discovery only
Anonymous leakers, renders, "concept" videos, benchmark-database sightings, case-maker leaks.

## Expert vocabulary for queries
SDK / API level, deprecation window, entitlement, background execution limits, app-store policy, alternative app stores and DMA obligations, SKU and model number, region variant, band support, RF front-end, modem generation, eSIM / iSIM, satellite D2D / NTN, UWB, thermal envelope, display driver.

## Signpost calendar
- Developer conferences (spring–summer): API mandates signal intended app behaviour.
- OS beta cycles (summer) → release (autumn); spring and autumn hardware launch windows.
- Regulator filings 1–8 weeks before a launch; certification listings weeks to months earlier.
- App-store policy updates (often quarterly) and regulatory deadlines (DMA, state laws).

## Pitfalls specific to this domain
- One analyst note becomes fifty headlines; trace the origin and count it once.
- Renders and concept videos are not evidence. Supply-chain reports are weighted by the reporter's record.
- "Supports" (silicon) vs "enabled" (SKU, region, carrier). The spec page per model number is the resolution source.
- Platform "deprecation" vs removal; check the API level at which it actually stops working.
- Vendors do not pre-announce; forced API migrations are the strongest intent signal.
